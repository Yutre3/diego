# Guía para explicar el proyecto al profesor

## Inicio

Nuestro proyecto corresponde al Caso 6, Sistema de Pasajeros de Hotel Duerme Bien. La idea es reemplazar planillas Excel por un sistema que gestione habitaciones, pasajeros, reservas, check-in, check-out, ocupación y costos.

## 1. Repositorio

Todo el trabajo fue documentado dentro del repositorio. Separamos cada parte del proyecto en archivos y usamos Git para mantener un historial de cambios.

Mostrar:
- README.md
- docs/00_bitacora_desarrollo.md
- historial de commits

## 2. Requerimientos

Primero organizamos los requerimientos y diferenciamos lo que viene del caso de las propuestas necesarias para completar el modelo.

## 3. Casos de uso

Identificamos los actores Administrador y Encargado de hotel y las funciones que cada uno puede realizar.

## 4. Diagrama de flujo

Representamos el proceso desde el inicio de sesión hasta reservas, check-in, check-out y actualización de datos.

## 5. Base de datos

Separamos huéspedes, habitaciones, reservas, estadías y usuarios para evitar datos repetidos y mantener relaciones claras.

## 6. Mockups

Diseñamos las pantallas principales antes de programar: login, panel, reservas, check-in y check-out.

## 7. Kanban y trazabilidad

Usamos Kanban para organizar el avance y una matriz de trazabilidad para comprobar que los requisitos estén representados.

## 8. Historial de Git

Cada etapa importante debe quedar registrada en un commit. Esto permite demostrar cómo fue evolucionando el proyecto.

## Cierre

El repositorio documenta el proceso completo: requerimientos, casos de uso, flujo, base de datos, interfaz, planificación y explicación final.

## Preguntas posibles

**¿Por qué usar un repositorio?**  
Porque mantiene los archivos ordenados, registra cambios y demuestra el avance.

**¿Por qué no solo un informe?**  
Porque cada archivo documenta una parte del desarrollo y el informe resume el resultado.

**¿Qué viene del caso?**  
Habitaciones, huéspedes, ocupación, costos, usuarios, informes, check-in, check-out y reservas.

**¿Qué es propuesta?**  
Los detalles que el caso no define expresamente, como ciertos campos, validaciones o decisiones de diseño.
