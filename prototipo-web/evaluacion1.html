Evaluación 1 - Toma de requerimientos

Contenido solicitado por la pauta IEEE 830 adaptada.

Lo que pide la pauta

Introducción; descripción general; requisitos funcionales y no funcionales preliminares; reglas de negocio; entrevista simulada; factibilidad técnica y de negocio; organización de requerimientos con trazabilidad para Evaluación 2.

1. Introducción

1.1 Propósito

Definir de forma ordenada qué debe hacer el Sistema de Pasajeros del Hotel Duerme Bien antes de diseñar o programar la solución.

1.2 Alcance

El sistema considera habitaciones, huéspedes, asignación de habitaciones, ocupación, disponibilidad, reservas, check-in, check-out, cálculo de costos por pasajero, usuarios e informes de ocupación y reservas.

1.3 Público objetivo

  • Administrador del hotel.
  • Encargados del hotel.
  • Equipo de desarrollo.
  • Docente que revisa el proyecto.

1.4 Definiciones

TérminoDefinición usada
Huésped / pasajeroPersona registrada para alojarse en el hotel.
HabitaciónEspacio para alojar huéspedes, con capacidad y orientación.
ReservaRegistro previo asociado a una futura estadía.
Check-inIngreso del huésped y asignación de habitación.
Check-outSalida del huésped y liberación de habitación.
OcupaciónCondición de una habitación que está siendo utilizada.
DisponibilidadCondición que permite determinar si una habitación puede asignarse.

2. Descripción general

2.1 Perspectiva del producto

El proyecto nace para reemplazar las planillas Excel utilizadas por el hotel para registrar pasajeros y habitaciones.

2.2 Funciones generales

  • Registrar habitaciones con capacidad y orientación.
  • Registrar huéspedes y asignarlos.
  • Controlar ocupación y disponibilidad.
  • Gestionar reservas.
  • Realizar check-in y check-out.
  • Calcular costos por pasajero.
  • Gestionar usuarios.
  • Consultar informes de ocupación y reservas.

2.3 Clases de usuario

Administrador: perfil de administración. Encargado de hotel: perfil operativo. El caso no entrega una matriz exacta de permisos.

2.4 Entorno operativo

El Caso 6 no define tecnología, sistema operativo, lenguaje ni motor de base de datos. Una aplicación web es una decisión de prototipo, no un requisito oficial.

2.5 Restricciones

  • La ocupación y disponibilidad deben ser coherentes.
  • Deben existir los perfiles administrador y encargado.
  • Las habitaciones deben manejar capacidad y orientación.
  • No puede definirse una fórmula definitiva de costos sin información adicional.

2.6 Supuestos y dependencias por validar

  • Datos obligatorios del huésped.
  • Identificador exacto de habitación.
  • Fórmula de costos.
  • Reglas de modificación/cancelación de reservas.
  • Estados exactos de reserva.
  • Permisos detallados por perfil.

4. Requisitos no funcionales preliminares

El Caso 6 no entrega requisitos no funcionales explícitos. Por eso cualquier RNF se mantiene como propuesta a validar.

IDPropuesta

RNF-03La información debe almacenarse de forma persistente en una implementación real.

5. Reglas de negocio

  • Una habitación ocupada no debe mostrarse como disponible.
  • El check-in debe dejar registrada la habitación asignada.
  • El check-out debe liberar la habitación.
  • La ocupación debe respetar la capacidad registrada.
  • El costo por pasajero debe calcularse automáticamente.
  • El sistema debe considerar administrador y encargado de hotel.
  • Los informes deben usar información de ocupación y reservas.

6. Entrevista simulada

¿Cuál es el problema?
El hotel utiliza Excel y necesita un sistema para gestionar habitaciones y pasajeros.

¿Qué información de habitaciones se necesita?
Capacidad y orientación; otros identificadores deben validarse.

¿Qué se hace con los huéspedes?
Registrarlos y asignarlos a habitaciones.

¿Qué debe controlarse?
Ocupación y disponibilidad.

¿Qué usuarios existen?
Administrador y encargados de hotel.

¿Cuáles son los procesos principales?
Reservas, check-in y check-out.

¿Se calcula el costo?
Sí, automáticamente por pasajero; la fórmula no está definida.

¿Qué informes se necesitan?
Ocupación y reservas.

7. Factibilidad inicial

7.1 Técnica

El alcance puede representarse mediante una aplicación y un modelo relacional. No se indican integraciones externas obligatorias en el Caso 6.

7.2 De negocio

La solución responde al problema declarado: reemplazar planillas Excel y concentrar información de huéspedes, habitaciones, reservas y ocupación.
