Base del material entregado

Esta página separa lo que viene del Caso 6 de las decisiones técnicas necesarias para que el prototipo funcione.

Definición de proyectos(1).docx

Base funcional del sistema: habitaciones con capacidad y orientación, huéspedes asignados, ocupación/disponibilidad, costo automático por pasajero, usuarios administrador/encargados, informes de ocupación/reservas y procesos de check-in, check-out y reservas.

MOCKUP_COMPLETO(1).pdf

Se aplicó la secuencia Sketch → Wireframe → Mockup → Prototipo. El prototipo es navegable y permite probar interacción, botones y validaciones. También se aplicó diseño responsive.

CASOS_DE_USO_como_iniciar(1).pdf

Se utilizaron actores por rol, nombres de casos de uso comenzando con verbos, límite de sistema y relaciones legibles.

CASOS_DE_USO_extend_y_include(1).pdf

Se mantuvo el modelo simple y se evitó usar include/extend para representar el orden de ejecución.

MODELO_E_R_NORMALIZACION.pdf

El modelo de datos y la normalización se organizaron con 1NF, 2NF y 3NF, buscando evitar redundancia, problemas de actualización y dependencias incorrectas.

Diagramas de Clase(1).pdf y guía

El diagrama complementario utiliza nombre de clase, atributos, operaciones, multiplicidad y relaciones UML. Se mantiene como complemento porque la Evaluación 2 no lo enumera como entrega obligatoria.

Github_Git_VSCode.docx

El repositorio mantiene historial de commits, ramas y documentación del trabajo realizado.

Reiniciar demostración

Restaura los datos de prueba sin cambiar los archivos del repositorio.

Los elementos no definidos literalmente por el Caso 6 se muestran como decisiones técnicas de demostración y no como requisitos oficiales.
